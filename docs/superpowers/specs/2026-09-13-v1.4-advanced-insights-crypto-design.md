# Pecunia v1.4 — Advanced Insights, Forecasting, Crypto & Dashboard KPIs (Design)

**Status:** approved 2026-09-13. Epic of 5 tracks, naming continues the series (v1.1 = A–F, v1.2 = G–N) → **v1.4 = O–S**.

## Goal

Turn Pecunia from a *recording* tool into a *forward-looking* one: project the near future from the recurring commitments we already track (subscriptions, planned/recurring transactions, loans), surface the money metrics a personal-finance user actually watches (savings rate, committed cost, net-worth movement, goals), let the portfolio track crypto with automatic prices, and give every list screen a proper summary total.

## Global constraints

All work follows `docs/CONVENTIONS.md`:
- **§4 money** = integer minor units, never float, **never summed across currencies** (every aggregation is a per-currency map, exactly like the existing `/analytics/*`).
- Services **flush**, routers **commit**; services are **clock-free** — `today: date` is passed in from the router (`date.today()`), never read inside the service.
- Every table is **workspace-scoped**; mutations emit events → audit/activity with the field allowlists.
- StrEnum + CHECK constraints; the SQLAlchemy naming convention drives constraint/index names (parity via `compare_metadata`).
- Frontend: Tailwind v4 `--pc-*` tokens only (no raw hex), TanStack Query with the `qk` key factory, Vitest + Testing Library. Respect the mobile-responsive work (16px inputs, `min-w-0`, `overflow-x-auto` for wide content, `flex-wrap` clusters).
- **Conventional commits, NO trailers.** Implementer subagents run **Sonnet**; each uses `superpowers:subagent-driven-development` (TDD). Every subagent establishes its own baseline by running the full suite at branch start (counts drift; do not hardcode).

## Locked decisions (from brainstorming)

1. All four dashboard features ship.
2. Crypto refresh = on-demand button **and** a daily automatic job.
3. Forecast horizon = **6 months**.
4. Goal progress source = **flexible** (account balance / portfolio value / net worth / manual).
5. One epic, tracks built in parallel, a single whole-branch review at the end.
6. Daily crypto job **default ON**, env-toggleable, degrades gracefully offline.
7. Forecast visual: **solid** = history, **dashed** = known committed events, **shaded band** = + average variable-spend estimate.

## Track O — Forecasting engine + projected charts

**Backend — `ForecastService` (`api/src/pecunia/services/forecast.py`), clock-free.**
`forecast(workspace_id, *, today: date, months: int = 6) -> {currency: {net_worth: [...], cash: [...]}}`. For each of the next `months` month-ends it produces two per-currency series:

- **Cash projection.** Start value = current summed account balances (per currency). Then apply every **dated future cash event** falling in each month: planned/recurring `ScheduledTransaction` occurrences (signed), `Subscription` renewals (expense) expanded across the horizon by billing cycle, `Loan` planned payments (cash out) expanded by `payment_frequency`, and recurring income. A point carries `{date, value_minor, lower_minor, upper_minor, projected: true}`.
- **Net-worth projection.** Start = `SnapshotService.net_worth_as_of(today)`. Each month adds projected income minus projected expenses (a loan *principal* payment is net-worth-neutral — cash down, debt down — so it does not move the net-worth line, only the cash line; document this asymmetry in the service).

**Recurrence expansion** is a pure helper (`expand_occurrences(anchor_date, frequency, horizon_end)`), unit-tested independently, reused for subscriptions/planned/loans.

**Variable-spend band.** Compute the average monthly **non-recurring** expense from the last N (=6) months of history. The central (dashed) line = committed events only; `upper/lower` widen each successive month by ± that average (uncertainty grows with distance). Honest and explainable — no statistical black box.

**Endpoint:** `GET /api/v1/analytics/forecast?months=6` (`require_workspace` + `require_initialized`; router passes `today`; clamp `months` to a sane 1–24). Returns the per-currency envelope.

**Frontend.** A reusable recharts treatment: solid `<Line>` over history, a **dashed** `<Line strokeDasharray>` over the projected tail, and an `<Area>` for the `lower..upper` band. A zero `<ReferenceLine>` on the cash chart flags going negative. Applied to: the **net-worth-over-time** chart (dashboard + Insights, projected tail appended) and a **new cash-balance-forecast** chart on Insights. Hook `useForecast()` + `qk.analytics.forecast(months)`.

**Tests:** occurrence expansion (each frequency, DST-free date math); the two projections from a fixture workspace (committed events land in the right month, per-currency isolation, loan-payment net-worth neutrality, band widening); frontend renders solid+dashed+band and the zero reference from a mocked response.

## Track P — Refined screens (per-currency totals)

A small **summary header** on each list screen, grouped **by currency**, computed client-side from the already-fetched bounded (`limit=200`) list — no new endpoint unless pagination would truncate (none do today):

- **Accounts:** total balance (per currency), incl. negatives.
- **Portfolio:** grand total across all portfolios (each `value_minor` already computed).
- **Loans:** total borrowed, total lent, total remaining.
- **Assets:** total current value.
- **Subscriptions:** standardize the existing monthly + annual rollup into the shared header component.
- **Planned:** total upcoming (next occurrence sum, signed).
- **Transactions:** in / out / net for the **current filter** (from the loaded page; label as "this page" when `next_cursor` present, to stay honest about keyset paging).

A shared `<SummaryHeader>` presentational component (tokens, responsive, `flex-wrap`) keeps them consistent. **Tests:** per-currency grouping, negatives, empty states, the "this page" honesty label on Transactions.

## Track Q — Crypto price sync

**Model.** `Holding` gains nullable `coingecko_id` (migration **0003**, `down_revision="0002"`). Non-null ⇒ auto-priceable. (`symbol` stays free-text; the coin id is the unambiguous key.)

**Provider.** `CryptoPriceProvider` protocol with a `CoinGeckoPriceProvider` implementation → `GET /api/v3/simple/price?ids=<csv>&vs_currencies=<cur>` (keyless public endpoint, one call per distinct currency). Injected as a dependency so tests pass a **fake** — zero real HTTP in the suite. Timeouts + errors caught and surfaced as a typed result, never an unhandled raise.

**Service.** `PriceRefreshService.refresh(workspace_id, *, today) -> {updated, skipped, errors}`: gather auto-priceable holdings, group by portfolio currency, one provider call per currency, record a `HoldingPrice` (`source="coingecko"`, `as_of=today`) per resolved holding. Reuses the existing price-recording path so net worth/analytics invalidation is unchanged.

**On-demand:** `POST /api/v1/portfolios/refresh-prices` → runs the refresh for the workspace, returns the summary.

**Daily job:** an **in-process async scheduler** started on API app startup (a guarded `asyncio` task; no extra container, no host cron). Runs the refresh once/24h for every workspace, wrapped so a provider/network failure logs and continues. Gated by `PECUNIA_ENABLE_PRICE_SYNC` (default `true`); when false the task never starts. The on-demand endpoint works regardless of the flag.

**Coin picker:** `GET /api/v1/portfolios/coins?q=` proxies a **cached** CoinGecko `/coins/list` (fetched once, memoized) and filters server-side, so the holding form gets a searchable id list without hammering the API.

**Egress note:** this is the first outbound call the app makes. Document it in the README/deploy guide (needs internet egress from the API container; fully optional).

**Frontend.** Holding form: a "crypto" affordance with a coin-search autocomplete (`coingecko_id`). Portfolio/holdings screen: an "Update prices" button (calls the endpoint, toasts the summary). Latest-price badge shows `source` + relative `as_of` ("via CoinGecko · 2h ago").

**Tests:** refresh with a fake provider (groups by currency, never cross-currency, resolves/records prices, skips holdings without an id, handles an unknown coin and a network error); the scheduler's job function (unit — invoke it directly, don't test timing); the coins proxy filter + cache; frontend coin-picker and the update-prices button/summary.

## Track R — Dashboard KPIs (analytics only, no new table)

Three tiles, each a small analytics aggregation + a dashboard card, per currency:

- **Savings rate (month):** income − spend for the current month → amount + rate (`saved/income`), with a trend arrow vs the prior month. Reuses the cashflow computation.
- **Committed monthly cost:** Σ active subscriptions + Σ loan planned payments + Σ recurring planned expenses, each **normalized to a monthly figure** by its cycle/frequency, per currency, with a small breakdown. "What leaves before you spend anything."
- **Net-worth change:** `net_worth_as_of(today)` vs `net_worth_as_of(first_of_month)` → Δ, %, and the **top movers** (largest component/account/holding/loan deltas).

Endpoint(s): extend `/analytics` (e.g. `GET /analytics/summary`) returning these per currency; router passes `today`. **Tests:** each metric from a fixture (monthly normalization of every cycle, trend sign, per-currency, top-mover ordering); frontend tiles render figures/trend/breakdown and empty states.

## Track S — Savings goals (new domain)

**Model.** `goals` table (migration **0004**, `down_revision="0003"`): `id, workspace_id, name, target_minor, currency, target_date (nullable), source_kind (StrEnum: account|portfolio|net_worth|manual, CHECK), source_id (nullable — the account/portfolio id when applicable), manual_current_minor (nullable, for source_kind=manual), created_at`. Workspace-scoped; events → audit.

**Service.** CRUD + `progress(goal, *, today)`: resolves the **current** value from its source (account balance / portfolio value / net worth as-of today / the manual figure), returns `{current_minor, target_minor, pct}`. Currency must match the source's currency (validate; never cross-currency). **ETA** reuses Track O: project the source forward and return the month it reaches `target_minor` (or "not on track"). Clock-free.

**Endpoints:** `/api/v1/goals` CRUD + the computed `progress`/`eta` on the read model.

**Frontend.** A goals management screen (list + create/edit/delete, source selector) and a **dashboard widget** with a progress ring per goal + the ETA line. New nav item under "Plan". Hook + `qk.goals`.

**Tests:** progress per source kind, currency-match guard, ETA from a projected fixture (on-track vs not), CRUD; frontend ring + ETA + empty state.

## Cross-track coordination

- **Migrations:** only Q (`0003`) and S (`0004`) add tables/columns. Assign the revision ids up front. S chains onto `0003`, so **S builds after Q merges** (its worktree needs `0003` present to run alembic).
- **Dependency:** S's ETA consumes Track O → wire the ETA after O merges.
- **Build waves (max parallelism, quality preserved):**
  - **Wave 1 (parallel Sonnet worktrees):** O, P, Q, R. Only Q carries a migration in this wave (no collision). Each merges to `develop` after a per-track check.
  - **Wave 2:** S off updated `develop` (has `0003`; consumes O for the ETA).
- **Final:** one whole-branch review of the full v1.4 on `develop` (strong model), fixes, done. Owner pushes.

## Testing strategy

TDD per track (failing test → implement → green). Backend: pytest + testcontainers; **no real network** (crypto provider faked). Frontend: Vitest + Testing Library; recharts stubbed as today. `npm run build && lint && test` and `pytest` green with **0 new warnings** before each merge.

## Out of scope / deferred

FX conversion between currencies (still never summed across); intraday/streaming prices (daily + on-demand only); non-crypto market feeds (stocks/ETFs stay manual); interest amortization into loan `remaining_minor`; goal contributions ledger (progress is derived from the source, not a separate deposit log).
