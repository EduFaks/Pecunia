# Plan D (v1.1) — First-Class Transfers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make moving money between your own accounts a first-class **Transfer** — one action that creates a paired outflow/inflow, keeps both account balances correct, and is **excluded from income/spend** (a transfer is not earning or spending, just relocating your own money). Groundwork for the Track E cashflow graphs, which must not double-count transfers as income *and* expense.

**Architecture:** A `Transfer` entity is the first-class object; `TransferService.create` atomically creates the transfer plus **two transaction legs** — a `-amount` leg on the source account and a `+amount` leg on the destination account — each carrying `transfer_id`. Balances already derive from `Σ non-deleted transactions` (see `AccountService.balance`), so the two legs move both balances and net to zero across the workspace (net worth unchanged — correct). Legs are **managed only through `TransferService`**: the plain transaction endpoints refuse to create or mutate a transfer leg, preserving the pairing invariant. One migration `0009`.

**Tech Stack:** no new deps.

## Global Constraints
- Follow `docs/CONVENTIONS.md` (layering; transaction contract — services flush, routers commit; §4 money integer minor units; §6 keyset pagination + state-conflict codes; §7 events/allowlists; §8 testing/parity; §9 frontend tokens). Roadmap: Track D (before E graphs).
- **V1 scope — same-currency only:** both accounts must share a currency (the app has no FX in V1). A cross-currency transfer → 422. `amount_minor` is a positive magnitude in that shared currency.
- **Invariants:** a transfer's two legs always exist together; `from_account_id != to_account_id`; both accounts belong to the workspace; leg signs are `-amount` (source) and `+amount` (destination); a transaction with `transfer_id` set is a transfer leg and is **excluded from income/spend** (honored by E). Deleting a transfer deletes both legs (FK CASCADE). Legs are never created/edited/deleted through the transaction endpoints.
- Workspace-scoped (D7) + `is_demo`. Events for audit/activity. Conventional commits, **no trailers**. Baseline at branch start: backend 392 pytest, web 585 vitest green.

### Task 2: TransferService + endpoints + transfer-leg guards on the transaction API

**Files:** Create `api/src/pecunia/services/transfers.py`, `api/src/pecunia/api/transfers.py`; modify `api/src/pecunia/services/transactions.py` + `api/src/pecunia/api/transactions.py` (guard legs; return `transfer_id`), `api/src/pecunia/main.py` (mount), `api/src/pecunia/audit/actions.py` + `activity/templates.py` (transfer events); tests `api/tests/test_transfers.py` (+ transaction guard tests).

**Interfaces:**
- `TransferService(db)`:
  - `create(workspace_id, *, from_account_id, to_account_id, amount_minor, currency, description, occurred_on)` → validates: both accounts in the workspace (404 if not), `from != to` (422), both accounts' currency == the given currency (422 cross-currency), `amount_minor > 0` (422). Creates the `Transfer` + two `Transaction` legs (`-amount` on from, `+amount` on to, each `transfer_id=transfer.id`, `description`, `occurred_on`, no category/payee/project). Flush. Event `transfer.created` (+ an activity template). Returns the transfer.
  - `list` (keyset by created_at), `get`, `update` (amount/description/occurred_on/accounts — **re-sync both legs** to match; re-validate currency/distinct/amount), `delete` (delete the transfer; CASCADE removes both legs) — each emits the matching event.
  - `legs(transfer)` helper → the two leg transactions (for the out shape).
- Endpoints `/api/v1/transfers` (require_workspace, require_initialized): POST 201, GET list, GET/{id}, PATCH/{id}, DELETE/{id} (204). `TransferOut` = {id, from_account_id, to_account_id, amount_minor, currency, description, occurred_on, is_demo, created_at} (+ optionally the two leg ids).
- **Transaction endpoint guards (the invariant):** the transaction CREATE endpoint does NOT accept `transfer_id` (ignore/omit it from `TransactionIn`); `TransactionOut` DOES return `transfer_id` (so the UI can label a leg + route edits to the transfer). `update`/`delete` on a transaction whose `transfer_id` is set → **409 `MANAGED_BY_TRANSFER`** (a leg is edited/removed only via its transfer). Add tests.

- [ ] **Step 1: Failing tests:** create a transfer → 201, transfer persisted, exactly two legs created with correct signs/accounts/`transfer_id`, and both account balances move by ∓amount; `from==to` → 422; cross-currency accounts → 422; foreign account → 404; listing/keyset; update re-syncs both legs (balances follow); delete removes the transfer AND both legs (balances revert); a transaction leg cannot be updated or deleted via the transaction API (409); the plain transaction create ignores/rejects `transfer_id`; `TransactionOut.transfer_id` is populated for legs and null otherwise.
- [ ] **Step 2–4:** implement; parity + full suite green. **Step 5:** commit `feat: transfer service, endpoints, and transaction-leg guards`.

## Self-review notes
- **Coverage:** Transfer entity + two-leg orchestration (T1/T2), the managed-leg invariant enforced at the transaction API (T2), same-currency/distinct-account/foreign validation (T2), full UI incl. transfer form, leg labeling, and edit-via-transfer (T3). Balances stay correct because legs are ordinary transactions; net worth unchanged (legs net to zero). CASCADE keeps a transfer and its legs atomic.
- **Consistency:** `transfer_id` mirrors the other tx FKs; TransferService follows the flush-not-commit contract and the event/allowlist pattern; pickers reuse the account select.
- **Excluded from income/spend:** the `transfer_id`-is-set marker is the exclusion signal; Track E's cashflow/income/spend sums filter `transfer_id IS NULL`. This plan only establishes the marker + keeps balances right; the graphs consume it in E.
- **Deferred:** cross-currency transfers (needs FX, out of V1 scope); the income/spend graphs themselves (Track E).
