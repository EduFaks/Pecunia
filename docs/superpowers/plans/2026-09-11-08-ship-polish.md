# Plan 08 — Ship Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Complete the "clone → `cp .env.example .env` → `docker compose up -d` → open the browser → wizard → app" experience on the canonical three-container topology (`pecunia-web`, `pecunia-api`, `pecunia-db`): an nginx `pecunia-web` that serves the built SPA and proxies the API, `pecunia doctor` diagnostics, compose hardening, a finished README, dependency-audit cleanup + the last responsive polish, and a full 3-container end-to-end verification of the real shipped artifact.

**Architecture:** `pecunia-web` = multi-stage image (node build of `web/` → nginx serving the static SPA with history fallback + reverse-proxying `/api` to `pecunia-api`). The published port moves to `pecunia-web`; `pecunia-api` stops publishing (internal only). Because requests now reach the API through the proxy, the API must trust it: `pecunia-web` gets a static IP on the compose network and `PECUNIA_TRUSTED_PROXIES_RAW` names it, so `X-Forwarded-For` is honored (per-IP throttling + audit IPs stay real — the Plan 02/03 carryover). nginx forwards the original `Host` so the API's Origin/Host CSRF check still matches.

**Tech Stack:** nginx (alpine), the existing node/uv toolchains, `typer` for the CLI. No new runtime services (still three containers).

## Global Constraints

- **Three containers, no more** (spec D6): `pecunia-web`, `pecunia-api`, `pecunia-db`. No Redis/queues.
- **The journey must need nothing manual** beyond `cp .env.example .env && docker compose up -d`: no DB creation, SQL, migrations, user creation, frontend build, or secret generation by hand (spec "First-Run Docker Experience").
- **Proxy correctness:** nginx passes the original `Host` (so `check_origin` matches) and sets `X-Forwarded-For`/`X-Forwarded-Proto`; the API trusts only the `pecunia-web` static IP via `PECUNIA_TRUSTED_PROXIES_RAW`. `Secure` cookies activate when `X-Forwarded-Proto=https` (documented for users terminating TLS upstream).
- **Secrets:** unchanged behavior (auto-generate+persist if empty; refuse weak configured key). `.env.example` stays all-optional-with-working-defaults; document the production warning to set a strong `PECUNIA_SECRET_KEY` and to front Pecunia with HTTPS.
- **CLI is not mandatory** for setup — `pecunia doctor` is diagnostic only.
- Follow `docs/CONVENTIONS.md`. Backend tests (`cd api && uv run pytest`) and web tests (`cd web && npm run test`) stay green. Conventional commits, **no trailers**, one task per commit. Docker verification uses `docker compose` at the repo root.

### Task 1: `pecunia-web` nginx container + compose topology + proxy trust

**Files:** `web/Dockerfile`, `web/nginx.conf`, `docker-compose.yml`, `.env.example`.

**Interfaces:** the three-container stack where the browser hits `pecunia-web` on `${PECUNIA_PORT:-8480}` and everything works end to end.

- [ ] **Step 1: `web/Dockerfile`** (multi-stage):

```dockerfile
# --- build the SPA ---
FROM node:20-alpine AS build
WORKDIR /app
COPY web/package.json web/package-lock.json ./
RUN npm ci
COPY web/ ./
RUN npm run build

# --- serve with nginx ---
FROM nginx:1.27-alpine
COPY web/nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

(Build context is the repo root so both `web/` and the api aren't needed — set `build.context: .` + `dockerfile: web/Dockerfile` in compose, or context `./web` with the Dockerfile pathed accordingly; pick one and keep the COPY paths consistent. Simplest: `context: ./web`, `dockerfile: Dockerfile`, and drop the `web/` prefixes in COPY.)

- [ ] **Step 2: `web/nginx.conf`**:

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    # Security headers (defense in depth; the app is self-hosted, same-origin)
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "same-origin" always;

    # API → pecunia-api. Preserve the browser's Host so the API's Origin/Host
    # CSRF check still matches; forward the real client IP + scheme.
    location /api/ {
        proxy_pass http://pecunia-api:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
    }

    # SPA history fallback — every non-file route serves index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

(Note: `X-Forwarded-For $remote_addr` OVERWRITES rather than appends — deliberate, so a client can't spoof it, per the Plan 03 `.env.example` warning. Do NOT use `$proxy_add_x_forwarded_for` here.)

- [ ] **Step 3: `docker-compose.yml`** — add the network with a subnet, give `pecunia-web` a static IP, wire trust:

```yaml
services:
  pecunia-db:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: ${PECUNIA_DB_USER:-pecunia}
      POSTGRES_PASSWORD: ${PECUNIA_DB_PASSWORD:-pecunia}
      POSTGRES_DB: ${PECUNIA_DB_NAME:-pecunia}
    volumes:
      - pecunia_db_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${PECUNIA_DB_USER:-pecunia} -d ${PECUNIA_DB_NAME:-pecunia}"]
      interval: 5s
      timeout: 3s
      retries: 12
      start_period: 30s
    restart: unless-stopped
    networks: [pecunia]

  pecunia-api:
    build: ./api
    depends_on:
      pecunia-db:
        condition: service_healthy
    environment:
      PECUNIA_DATABASE_URL: postgresql+asyncpg://${PECUNIA_DB_USER:-pecunia}:${PECUNIA_DB_PASSWORD:-pecunia}@pecunia-db:5432/${PECUNIA_DB_NAME:-pecunia}
      PECUNIA_SECRET_KEY: ${PECUNIA_SECRET_KEY:-}
      PECUNIA_CONFIG_DIR: /data/config
      PECUNIA_TRUSTED_PROXIES_RAW: ${PECUNIA_WEB_IP:-172.31.0.2}
      PECUNIA_SERVER_NAMES_RAW: ${PECUNIA_SERVER_NAMES_RAW:-}
    volumes:
      - pecunia_config:/data/config
      - pecunia_files:/data/files
    restart: unless-stopped
    networks: [pecunia]

  pecunia-web:
    build:
      context: ./web
      dockerfile: Dockerfile
    depends_on: [pecunia-api]
    ports:
      - "${PECUNIA_PORT:-8480}:80"
    restart: unless-stopped
    networks:
      pecunia:
        ipv4_address: ${PECUNIA_WEB_IP:-172.31.0.2}

networks:
  pecunia:
    ipam:
      config:
        - subnet: ${PECUNIA_SUBNET:-172.31.0.0/24}

volumes:
  pecunia_db_data:
  pecunia_config:
  pecunia_files:
```

### Task 2: `pecunia doctor` CLI

**Files:** `api/src/pecunia/cli.py`, `api/pyproject.toml` (typer + script entry); test `api/tests/test_doctor.py`.

**Interfaces:** `docker compose exec pecunia-api pecunia doctor` runs a set of checks and exits non-zero if any critical check fails. Checks: **database** connectivity + that migrations are at head (compare Alembic current vs head); **storage** — the config + files volumes are writable; **secret** — a key is resolved and (if configured) not weak, and the persisted keyfile is `0600`; **migrations** — current == head; **backup** — best-effort note of the newest `pg_dump` in a conventional backups location if present (informational, never fails). Output is a readable checklist (✓/✗ per line) using plain text; `doctor` returns exit code 0 only if all non-informational checks pass. Factor the checks as pure-ish functions so they're unit-testable without a full container.
