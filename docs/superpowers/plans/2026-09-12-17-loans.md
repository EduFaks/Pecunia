# Plan (v1.1 domain) — Loans Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A **Loans** domain (MoneyMatter parity) — track a loan's **principal** (original amount), a **planned payment** (how much / how often / next due), the **payments made** (a ledger), and the **remaining** balance and progress. A loan is a real liability (or, if you lent money out, a receivable), so its remaining balance rolls into **net worth** per currency — the completion that makes net worth honest.

**Architecture:** A `Loan` entity (principal, currency, direction borrowed|lent, planned payment + frequency + next_due, optional interest rate for display) + a `LoanPayment` ledger (amount, paid_on). Computed: `paid_total = Σ payments`, `remaining = max(principal − paid_total, 0)`, progress = paid/principal. Net-worth integration mirrors Portfolio: extend `SnapshotService.net_worth_as_of` and web `netWorthByCurrency` — a **borrowed** loan subtracts its remaining (as of the date, reconstructed from `principal − Σ payments with paid_on ≤ date`), a **lent** loan adds it. One migration `0013`.

**Money rule:** integer minor units throughout (`principal_minor`, `amount_minor`, `planned_payment_minor`). Interest rate stored as basis points (`interest_rate_bps`, integer) for DISPLAY only — V1 does not amortize/compute interest into remaining (remaining = principal − payments). Never float.

### Task 2: LoanService + endpoints + net-worth integration

**Files:** Create `api/src/pecunia/services/loans.py`, `api/src/pecunia/api/loans.py`; modify `api/src/pecunia/services/snapshots.py` (net-worth integration), `api/src/pecunia/main.py`, `api/src/pecunia/audit/actions.py` + `activity/templates.py`; tests `api/tests/test_loans.py` + extend `api/tests/test_snapshots.py`.

**Interfaces:**
- `LoanService(db)` (flush, never commit): loan CRUD (create/list keyset/get/update/delete); `record_payment(loan, *, amount_minor, paid_on, note=None)` appends a `LoanPayment` (event `loan_payment.recorded`); `list_payments(loan)`; `delete_payment`. Helpers `paid_total_minor(loan, *, on_date=None)` = `Σ LoanPayment.amount_minor with paid_on ≤ on_date|(all)`; `remaining_minor(loan, *, on_date=None)` = `max(loan.principal_minor − paid_total_minor, 0)`. Validate positive amounts (422). Events `loan.created/updated/deleted`.
- Endpoints `/api/v1/loans` (require_workspace, require_initialized): loan CRUD; nested `GET/POST /{id}/payments`, `DELETE /{id}/payments/{pid}`. `LoanOut` = the loan fields + computed `paid_total_minor`, `remaining_minor`. `LoanPaymentOut` = its fields.
- **Net-worth integration:** extend `SnapshotService.net_worth_as_of(on_date)` — for each loan, compute `remaining = max(principal − Σ payments with paid_on ≤ on_date, 0)`; a `borrowed` loan does `add(currency, -remaining)` (liability), a `lent` loan does `add(currency, +remaining)` (receivable), grouped by the loan's currency. This makes `capture`/`backfill`/analytics reflect debts. Update `test_snapshots.py` to assert a borrowed loan REDUCES net worth by its remaining and that a payment (with an earlier paid_on) reduces the liability at later dates.

## Self-review notes
- **Coverage:** loan entity + direction + planned payment + payments ledger (T1); CRUD + paid/remaining + the signed net-worth integration (T2); full UI incl. list w/ progress, payments ledger, record payment, and the net-worth tile update (T3). Remaining is reconstructable from the payment ledger by date, so net-worth-over-time reflects debt paydown.
- **Consistency:** mirrors Portfolio's net-worth-integration pattern (extend `net_worth_as_of` + web `netWorthByCurrency`, now a signed term); money integer minor units; StrEnum+CHECK for direction/frequency; reuses the §9.1 progress-fill; allowlist has no secret-like fields.
- **V1 simplifications (documented):** no interest amortization (remaining = principal − payments; `interest_rate_bps` is display-only); a `LoanPayment` is a standalone record, not linked to an account transaction (linking is a future enhancement — avoids double-entry scope here).
- **Deferred:** amortization schedules with interest, linking a payment to the funding transaction, payoff projections — future scope.
