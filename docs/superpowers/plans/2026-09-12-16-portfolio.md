# Plan (v1.1 domain) — Portfolio / Investment Holdings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A **Portfolio** domain (MoneyMatter parity) — track investment holdings: what you hold in each investment account, the quantity, a **manually-updated** price, and the resulting market value; and roll that value into net worth. No external market-data feeds (manual pricing, consistent with Pecunia's philosophy).

**Architecture:** Mirrors the `Asset`/`AssetValuation` pattern. A `Portfolio` (an investment account) contains `Holding`s (name/symbol + quantity); each holding's price is updated manually and recorded as a `HoldingPrice` (as-of history, exactly like `AssetValuation`) so portfolio value participates correctly in **net-worth-over-time**. Market value = `quantity × latest_unit_price`. The critical integration: extend `SnapshotService.net_worth_as_of` (backend) and `netWorthByCurrency` (web) to include portfolio value per currency. One migration `0012`.

**Money/quantity rule:** money stays **integer minor units** (`unit_price_minor`, `value_minor`). `quantity` is NOT money — store it as `Numeric(28, 8)` (fractional shares/crypto). `value_minor = round(quantity × unit_price_minor)` as an integer. Never use float for money.

## Global Constraints
- Follow `docs/CONVENTIONS.md` (layering; services flush/routers commit; §4 money minor units — never float, never cross-currency; §6 keyset; §7 events/allowlists; §8 parity; §9 tokens; clock-free services). Workspace-scoped (D7) + `is_demo`.
- **Historical approximation (documented):** `net_worth_as_of(date)` values a holding as `current quantity × (latest HoldingPrice with as_of ≤ date)`. Quantity history (buy/sell ledger) is out of V1 scope, so historical net worth uses current quantity with the date-appropriate price — accurate going forward, a reasonable approximation for the backfilled past. Note this in the service docstring.
- Conventional commits, **no trailers**. Baseline at branch start: backend 483 pytest, web 679 vitest green.

### Task 2: Services + endpoints + **net-worth integration**

**Files:** Create `api/src/pecunia/services/portfolios.py`, `api/src/pecunia/api/portfolios.py`; modify `api/src/pecunia/services/snapshots.py` (net-worth integration), `api/src/pecunia/main.py`, `api/src/pecunia/audit/actions.py` + `activity/templates.py`; tests `api/tests/test_portfolios.py` + extend `api/tests/test_snapshots.py`.

**Interfaces:**
- `PortfolioService(db)` (flush, never commit): portfolio CRUD (create/list keyset/get/update/delete); holding CRUD scoped to a portfolio (add_holding/list_holdings/update_holding/delete_holding); `record_price(holding, *, unit_price_minor, as_of)` appends a `HoldingPrice`; helpers `holding_value_minor(holding, on_date=None)` = `round(quantity × latest unit_price with as_of ≤ on_date|today)` and `portfolio_value_minor(portfolio, ...)` = Σ holding values. Validate holdings belong to the portfolio/workspace (404). Events `portfolio.*`, `holding.*`, `holding_price.recorded`.
- Endpoints `/api/v1/portfolios` (require_workspace, require_initialized): portfolio CRUD; nested `/{id}/holdings` CRUD; `/{id}/holdings/{hid}/prices` POST (record price). `PortfolioOut` includes `value_minor` (current) + holding count; `HoldingOut` includes `quantity` (string), `latest_unit_price_minor`, `value_minor`.
- **Net-worth integration (critical):** extend `SnapshotService.net_worth_as_of(on_date)` to add, per currency, `Σ over holdings [ current quantity × (latest HoldingPrice.unit_price_minor with as_of ≤ on_date) ]`, grouped by the holding's PORTFOLIO currency (via the existing `add(currency, amount)` accumulator). Holdings with no price ≤ date contribute nothing. This makes `capture`/`backfill`/the analytics net-worth series include portfolios automatically. Update `test_snapshots.py` to assert a portfolio holding raises net worth at/after its first price date.

- **Documented approximation:** historical net worth uses current quantity × historical price (no quantity/buy-sell history in V1).
- **Deferred:** buy/sell transaction ledger per holding, cost-basis/gain-loss, dividends — future scope.
