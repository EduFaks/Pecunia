# Track M (v1.2) — Upcoming Dashboard Widget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A dashboard **Upcoming** panel — at a glance, what's coming: **planned** items due, **subscription** renewals, **loan** payments due (next 30 days), plus **over-budget** nudges. Uses existing data; no migration.

**Architecture:** A backend `AnalyticsService.upcoming(today, within_days, limit)` unifies the dated items from active scheduled transactions (`next_due`), active subscriptions (`next_renewal`), and loans (`next_due`) into one date-sorted list within a horizon, and separately lists budgets currently over (`actual_minor > amount_minor` in the current window). One endpoint; a dashboard card renders it. Clock-free (router passes `today`).

## Global Constraints
- Follow `docs/CONVENTIONS.md` (§4 money integer minor units, never cross-currency; §6; §9 tokens; services flush/routers commit; clock-free — dates passed in). Workspace-scoped. Conventional commits, **no trailers**. Baseline at branch start: backend 675 pytest, web 804 vitest.

### Task 1: Backend — `upcoming` aggregation + endpoint

**Files:** `api/src/pecunia/services/analytics.py` (add `upcoming`) + `api/src/pecunia/api/analytics.py` (endpoint); reuse `BudgetService.actual_minor` / `period.current_window`; tests `api/tests/test_analytics.py`.

**Interfaces:**
- `AnalyticsService.upcoming(workspace_id, *, today: date, within_days: int = 30, limit: int = 8) -> {due: list, over_budget: list}`:
  - `due` = a single list, sorted by `due_on` asc then a stable tiebreak, of the soonest items with `today <= due_on <= today + within_days`, each `{kind: "planned"|"subscription"|"loan", id, label, due_on, amount_minor, currency}`:
    - **planned**: active `ScheduledTransaction` rows (`is_active`) whose `next_due` is in range → label = description, amount = its `amount_minor` (signed), currency.
    - **subscription**: active `Subscription` (`status="active"`) whose `next_renewal` in range → label = name, amount = `amount_minor` (expense), currency.
    - **loan**: `Loan` rows with a non-null `next_due` in range (and a `planned_payment_minor` if set) → label = name, amount = `planned_payment_minor` (or null), currency; borrowed vs lent noted.
    Cap the merged list at `limit`.
  - `over_budget` = budgets whose `actual_minor(budget, today) > amount_minor` for the current window → `{budget_id, category label, amount_minor, actual_minor, over_minor, currency}` (skip budgets with no category / null actual). Reuse the budget-vs-actual computation.
  - Workspace-scoped; never cross-currency (each item carries its own currency; no summing). Clock-free (take `today`).
- Endpoint `GET /api/v1/analytics/upcoming?within_days=&limit=` (require_workspace+require_initialized; router passes `today=date.today()`; sensible defaults 30/8).

### Task 2: Frontend — Upcoming panel on the dashboard

**Files:** `web/src/features/analytics/useAnalytics.ts` (`useUpcoming`) + a `web/src/features/dashboard/UpcomingWidget.tsx`; mount on `web/src/features/dashboard/Dashboard.tsx`; `web/src/lib/queries.ts`; tests.

**Interfaces:** `useUpcoming()` fetches the endpoint. `UpcomingWidget` — a dashboard card ("Upcoming"):
- a **due** list, soonest-first: each row a lucide icon per kind (planned→CalendarClock, subscription→RefreshCw, loan→Landmark), the label, a relative/short **due date** (e.g. "in 3 days" / the date), and the amount (`MoneyText`, colored by sign); the row links to the relevant screen (`/planned`, `/subscriptions`, `/loans`).
- an **over-budget** section (if any): each an alert-toned row — category, "over by {over_minor}" (coral) of {amount_minor} — linking to `/budgets`.
- a clean empty state ("Nothing due in the next 30 days"). Tokens only; responsive; place it on the dashboard (e.g. beside/under the net-worth line or in the lower grid — keep the dashboard balanced).
