# Track L (v1.2) — Transaction Search & Filters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Find transactions fast — a **search box** (matches the description) plus **filters**: account, category, contact, date range, amount range, and type (income / expense / transfer). The list already filters by account/category/contact/project via keyset pagination; this adds the remaining server params and the UI to drive them.

**Architecture:** Extend the existing `TransactionService.list` + the list endpoint with the new query params (all optional, ANDed, keyset pagination preserved). A search/filter bar on `TransactionsScreen` threads the params into the existing infinite-list hook (each filter combo = its own query key). No migration.

- Follow `docs/CONVENTIONS.md` (§4 money integer minor units; §6 keyset pagination; §9 tokens; services flush/routers commit). Workspace-scoped. Conventional commits, **no trailers**. Baseline at branch start: backend 661 pytest, web 790 vitest.

### Task 1: Backend — search + filter params on the transactions list

**Files:** `api/src/pecunia/services/transactions.py` (`list`), `api/src/pecunia/api/transactions.py` (`list_transactions` query params); tests `api/tests/test_transactions.py`.

**Interfaces (all optional, ANDed with the existing account/category/contact/project filters; keyset ordering unchanged):**
- `q: str | None` — case-insensitive substring match on `description` (`ILIKE %q%`); ignore blank/whitespace.
- `date_from: date | None`, `date_to: date | None` — inclusive `occurred_on` range.
- `min_amount_minor: int | None`, `max_amount_minor: int | None` — on the **magnitude** `ABS(amount_minor)` (so "$10–$50" matches both a −5000 expense and a +5000 income); validate min ≤ max (422 if inverted, or just treat as empty — pick one, document).
- `type: Literal["income","expense","transfer"] | None` — `income` = `amount_minor > 0 AND transfer_id IS NULL`; `expense` = `amount_minor < 0 AND transfer_id IS NULL`; `transfer` = `transfer_id IS NOT NULL`.
- Endpoint exposes these as `Query(...)` params (`from`/`to` aliases for the dates like the analytics routes). Keep `deleted_at IS NULL`. Keyset (`created_at`/`id`) still applies with the WHERE filters.

- [ ] **Step 1: Failing tests:** `q` matches description case-insensitively + excludes non-matches; date range bounds inclusive; amount range on magnitude includes both signs within range and excludes outside; `type` income/expense/transfer partition correct (a transfer leg only under `transfer`, never income/expense); filters AND together (q + type + date); combined with an existing filter (contact_id) still works; keyset pagination still returns a stable page + cursor under filters; all workspace-scoped.
- [ ] **Step 2–4:** implement; full suite green. **Step 5:** commit `feat: transaction list search + date/amount/type filters`.

### Task 2: Frontend — search bar + filter controls on the transactions screen

**Files:** `web/src/features/transactions/TransactionsScreen.tsx` + `useTransactions.ts` (thread the params into the infinite-list hook + query key); a small `TransactionFilters` component; tests.

**Interfaces:** the list hook (`useTransactions`/`useTransactionsInfinite`) accepts an optional `filters` object `{ q, accountId, categoryId, contactId, type, dateFrom, dateTo, minAmountMinor, maxAmountMinor }` and includes it in the query key + querystring. `TransactionsScreen` gets:
- a **search input** (debounced ~250ms) bound to `q`;
- a **filter bar/panel**: account `Select`, `CategoryPicker`, `ContactPicker`, a **type** segmented control (All / Income / Expense / Transfer), a **date range** (from/to date inputs — reuse a range control or two date fields), an **amount range** (min/max money inputs);
- **active-filter chips** with individual removal + a **Clear all**;
- the existing DataList/keyset list re-queries as filters change; a "no results" empty state distinct from the "no transactions yet" empty state.
Tokens only; keep it responsive (filters wrap/stack on mobile — the wide bar collapses).

- [ ] **Step 1: Failing tests (vitest):** typing in the search box queries with `q` (debounced); selecting a type/category/contact/account filters the query; setting a date range and amount range threads them; active-filter chips render + removing one drops that param; Clear all resets; a filtered-to-empty result shows the "no results" state (not the first-run empty state).
- [ ] **Step 2–4:** `npm run build && lint && test` green (0 warnings). **Step 5:** commit `feat(web): transaction search bar + filters`.
