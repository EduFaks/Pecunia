# Pecunia V1 — Implementation Roadmap

**Spec:** `docs/superpowers/specs/2026-09-11-pecunia-v1-design.md` (approved 2026-09-11, incl. D7 workspaces)

V1 is decomposed into sequential plans. Each plan ends with working, testable software and is written/executed one at a time — later plans are drafted only when their predecessors are done, so they can reference real code instead of guesses.

| # | Plan | Deliverable ("done" means) |
|---|------|----------------------------|
| 01 | **Backend foundation** | `docker compose up` boots Postgres + API; migrations run automatically; `GET /api/v1/setup/status` → `{"initialized": false}`; secret auto-generation/validation works; test harness (pytest + Postgres testcontainer) established. |
| 02 | **Auth & setup initialize** | Users, workspaces, memberships, auth_sessions, login_attempts tables; Argon2id; JWT service with key ring; `POST /setup/initialize` (atomic, race-safe, auto-login); login/refresh (rotation + reuse detection)/logout/logout-all/me/sessions endpoints; throttling. |
| 03 | **Domain events, audit & activity** | In-process event bus + contextvars request context; append-only `audit_events` (trigger-enforced) & `activity_entries`; auth + setup events recorded; read endpoints with filters. |
| 04 | **Finance domain** | Accounts, transactions, projects + items, assets + valuations, budgets; workspace-scoped repositories; `is_demo` flag + demo seed/remove service; all mutations publish domain events. |
| 05 | **Frontend foundation** | Vite/React/TS + Tailwind wired to the `--pc-*` dark-first token system; auth client (in-memory access token, silent refresh); API client; router with setup/auth guards; base component kit (typography, surfaces, forms, focus states). |
| 06 | **Setup wizard UI** | The five-step wizard incl. hand-drawn stroke animations, zxcvbn meter, browser-hint prefills, demo-data step, finish transition; keyboard + reduced-motion complete. |
| 07 | **Application UI** | Dashboard, accounts/transactions/projects/assets/budgets screens, activity timeline, Settings → Security (Sessions + Audit Log UIs), demo-data chip. |
| 08 | **Ship polish** | `pecunia-web` nginx container + single published port; `pecunia doctor`; README quickstart; `.env.example` final; compose hardening & healthchecks; end-to-end smoke run of the clone→up→wizard journey. |

Ordering rationale: backend trunk first (01–04) so every UI plan binds to real endpoints; design system before wizard (05→06) because the wizard is the identity's proving ground; nginx/port topology last (08) once both web build and API shape are final — until then the API port serves directly.
